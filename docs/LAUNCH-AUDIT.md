## Anchor Deposit Webhook Fields Reference (Item 12 Verification)

Both `app/api/webhooks/anchor/route.ts` and `public.rpc_process_webhook_deposit` inspect the incoming Anchor credit webhook (`transaction.credit` / `virtual_nuban.credit` / `DepositAccount.credit`):

1. **Event Envelope:**
   - `id` / `data.id` -> stored idempotently as `anchor_event_id` in `public.webhook_events` and `public.deposits`.
   - `event` / `type` / `data.type` (`attributes.type === 'CREDIT'`).
2. **Transaction Routing & Amount (`data.attributes` or `attributes`):**
   - `accountNumber` / `destinationAccountNumber` -> matched against `public.transactions.virtual_account_number`.
   - `amount` -> integer **kobo** (`amount / 100` stored as NGN `NUMERIC(15,2)`).
   - `currency` (`NGN`).
   - `metadata.transactionId` -> cross-validated against `public.transactions.id` + `virtual_account_number`.
3. **Originating Sender Account Fields (`data.attributes.sender`, flat `attributes`, or JSON:API `included[]`):**
   - `sender.accountNumber` / `senderAccountNumber` -> `deposits.sender_account_number`, `transactions.sender_account_number`, and verified `DEPOSIT_SENDER` refund source encrypted via AES-256-GCM (`refund_account_ciphertext`, `refund_account_iv`, `refund_account_auth_tag`).
   - `sender.bankCode` / `senderBankCode` (CBN/NIP code) -> `deposits.sender_bank_code`, `transactions.sender_bank_code`.
   - `sender.accountName` / `senderName` -> `deposits.sender_name`, `transactions.sender_name`, `transactions.refund_destination_name`.
   - **JSON:API `included[]` Support:** `extractAnchorDepositSenderFields()` parses `included[]` items (`type` matching `counterparty`, `sender`, `deposit`, `payment`) cleanly as a fallback.
